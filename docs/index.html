INMARKET · 2024–2025 · ADTECH

Audience data, delivered at scale.

Spark / EMR · BigQuery · Cloud Composer · Python · Partner delivery

S Situation

A large audience platform needed to filter, transform, and deliver data to partners, each with different formats and destinations. Its EMR-based workflows were powerful but costly for recurring deliveries.

T Task

I maintained and improved the existing Spark platform while contributing to the architecture and buildout of its GCP successor.

A Action

I worked on Spark workloads on AWS EMR and customized partner delivery through APIs, SFTP, Snowflake, BigQuery, and cloud storage. The delivery code includes output partitioning and configurable connection retries.

For the GCP platform, I contributed to a design connecting a Flask API on GKE to Cloud Composer workflows, BigQuery transformations, and Python-based partner delivery.

R Result

The new GCP platform reduced infrastructure costs and simplified the pipeline architecture, making it easier to maintain, faster to deploy, and more scalable. My contribution combined ongoing production support with work on the modernization.

02
QUEXT / BLUE ORANGE DIGITAL · 2022–2023 · PROPTECH

Lease events into connected experiences.

Snowflake · Snowpipe · Streams · dbt · Amazon MWAA · ECS Fargate

S Situation

Quext’s smart-apartment platform needed to respond to move-ins and move-outs, but lease data lived in third-party property-management systems.

T Task

I led the design and implementation of a scalable, near-real-time integration platform to bridge external leasing systems and the IoT product.

A Action

We orchestrated API collection with Airflow on Amazon MWAA, using Lambda functions to retrieve data every five minutes. S3 files were loaded through Snowpipe into Snowflake raw tables with ingestion metadata and semi-structured VARIANT payloads.

I containerized dbt transformations on ECS Fargate. The models flattened source payloads into structured dimensions and a unified model; Snowflake Streams supported change detection. Quality checks included not-null, unique, and composite-key tests, plus deduplication before downstream joins.

R Result

The integration automated smart-lock updates, reduced manual work for property managers, and improved security and the tenant experience. The client recognized the team’s architecture and execution.

External APIs.
A consistent data model.
A real product outcome.

AIRBNB · PRODUCTION RELIABILITY

Designed to run.
Designed to rerun.

I use Airflow daily at Airbnb, where Airflow originated, supporting data platforms for vulnerability management.

↗ Astronomer Certification for Apache Airflow 3

S Situation

Production pipeline failures can block dependent tasks and delay downstream processing.

T Task

Recover affected workflows safely while maintaining data correctness.

A Action

We build idempotent pipelines. Once the cause is addressed, a common recovery is to clear the relevant upstream task in Airflow so it can rerun, then rerun affected downstream tasks as needed.

R Result

Most affected workflows recover through targeted reruns without rebuilding the entire pipeline.
